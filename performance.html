Computational Performance

Benchmarks across hardware, file formats, and parsing backends

Test System

Benchmark System

  • System: 500 ion pairs of 1-ethyl-3-methylimidazolium [C2mim] tetrafluoroborate [BF4]
  • Trajectory: 100 ns, 20,001 snapshots (Fig 3a,b) / 100,001 snapshots (Fig 3c)
  • Analysis: Einstein ionic conductivity
  • Details: Section S4 of Supporting Information

Hardware Platforms Tested

  • Mac: Apple Silicon (M-series)
  • Intel: x86_64 multi-core
  • AMD: x86_64 multi-core

Core Count Scaling (Figure 3a, 3b)

.xtc Format (Binary)

1 core → 8 cores Significant speedup

Performance scales with core count across all backends (MDAnalysis, Chemfiles, OVITO). Exact speedup factor varies by backend.

Binary formats benefit most from parallel parsing.

.pdb Format (Text)

1 core → 8 cores Moderate speedup

Text-based .pdb parsing is inherently slower than .xtc. Core scaling improvement is slightly less pronounced.

PDB mode optimized for multiprocessing snapshot handling.

GROMACS vs LAMMPS (Figure 3c)

100,001 Snapshots Comparison

GROMACS .xtc

Comparable performance to LAMMPS. Minor differences only in initial trajectory setup (MDAnalysis Universe creation).

LAMMPS .lammpstrj / .xtc

Similar throughput. LAMMPS requires --t_steps and --dump_frame for dt calculation.

Both engines show equivalent postprocessing performance — choice of MD engine doesn't affect analysis speed.

Hardware Platform Comparison (Figure 3d)

Apple Silicon (Mac) — Outstanding Performance

Calculations run substantially faster on Macs vs Intel/AMD with --n_cores = 8 for large files. Unified memory architecture and high memory bandwidth excel at data-intensive trajectory parsing.

Intel / AMD x86_64

Solid performance with good scaling. Performance depends on specific CPU generation, memory speed, and storage type (NVMe vs SSD vs HDD).

Key Insights

  • Text formats (.pdb, .lammpstrj): Chemfiles and OVITO dominate. Chemfiles: lowest memory for both. OVITO: fastest for .lammpstrj.
  • Binary formats (.xtc, .trr): Chemfiles and MDAnalysis are significantly faster (~10x vs text). MDAnalysis wins on memory efficiency for compressed formats.
  • Recommendation: Use .xtc with MDAnalysis for best balance of speed and memory. Use Chemfiles for lowest memory footprint on text formats.

Disk-Backed Processing (Figure 4c, 4d)

Memory Reduction

~50% reduction

Peak memory vs standard in-memory processing for 1M atom system (10,001 frames). Streams intermediate atomic/COM data to disk.

Execution Time

Comparable

Similar times for typical systems. I/O overhead may increase time for exceptionally large systems due to disk read latency.

Storage Hardware Impact

NVMe > SSD > HDD

Performance overhead depends on underlying storage. NVMe minimizes penalty; HDD may show noticeable slowdown.

Ultra-Low Memory

Single-core + --disk

For extremely constrained environments: combine --disk with --n_cores 1 to minimize RAM footprint (multiprocessing adds overhead per worker).

Optimization Recommendations

For Speed

  • Use .xtc binary format
  • Install MDAnalysis or Chemfiles
  • Use --n_cores = all available
  • Prefer Mac (Apple Silicon) or modern x86_64
  • Use --eh flag for conductivity (O(N) vs O(N²))

For Low Memory

  • Use --disk flag
  • Use Chemfiles backend (--chem)
  • Use --n_cores 1 or 2
  • Use .xtc with MDAnalysis (lowest for binary)
  • Process in chunks if possible

For HPC Clusters

  • --mp_mode forkserver or spawn
  • Explicit --n_cores per job allocation
  • Use --disk on shared filesystems
  • Pre-convert to .xtc if possible
  • Container/Singularity for reproducibility

Scaling Characteristics

Strong Scaling (fixed problem, more cores)

Near-linear speedup up to 8 cores for binary formats. Diminishing returns beyond 8–16 cores due to I/O contention and Python multiprocessing overhead.

Weak Scaling (larger problem, proportional cores)

Excellent for trajectory length scaling. Memory scales with --disk mode. Time scales linearly with frame count.

System Size Scaling

O(N) for EH conductivity/Onsager. O(N²) for standard Einstein cross-correlations (mitigated by --n_delta window limit). RDF: O(N²) but optimized with binning.
